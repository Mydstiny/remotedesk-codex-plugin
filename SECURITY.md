# Security and native permissions

RemoteDesk 0.3.0 uses the installed host engine's native tools. Docker is not required or invoked. Pairing uses a private CA, TLS 1.3, individual client certificates, project grants, writer leases and persisted operation receipts. State and keys are restricted to the current user; local administrators and compromised host processes remain outside this boundary.

Codex sessions default to `read-only`, network disabled and native `on-request` approvals. A controller may select `workspace-write`; writes inside that native sandbox may proceed without individual prompts. Commands requesting escalation and native file/permission requests are forwarded with their actual payload. Accept/decline/cancel are supported; rule amendments and session-wide grants are not. Native permission requests require an explicit `scope: "turn"` acknowledgement. An approved escalation may access the wider host according to Codex's native rules. The registered project is a working directory and RemoteDesk coordination scope, not a guarantee that the whole native agent can read only that directory.

DSH uses a copy of the official standard agent preset with delegation disabled, scoped to RemoteDesk agents. Its native sandbox restricts file writes; reads and network follow host-native behavior. Windows enforcement has upstream partial limitations. Every native write/edit/shell call requires one-time remote approval, including workspace-write mode. Sandbox override arguments are refused. Project instructions and native skills follow the native preset's read behavior. Remote job controls filter exact session ownership, including rejection of otherwise globally visible ownerless jobs. Existing agents, default model selection and preset roots are preserved.

Only the pinned native tool definitions are admitted for DSH; global tool extensions and delegation are unavailable. Codex MCP, plugins, hooks, browser integrations and delegation are disabled for remote sessions. These restrictions do not change the user's global engine configuration. This release aligns the core session/tool workflow; it does not expose every desktop integration.

Model credentials remain in the native host configuration. Authorized project text, native instructions, attachments and tool output may be sent to that configured provider and persisted in session history. Do not send passwords through chat. Native secret-input questions are not accepted through the bridge; complete authentication on the host.

The common writer lock excludes another RemoteDesk session using the same canonical project directory, including the other engine. Native managed background jobs/terminals retain that lock and can be listed or stopped. `execution.idle` means the adapter observed its native managed activity settle. It does not prove arbitrary detached descendants or other local editors/agents stopped. Cancellation never promises container-style process isolation.

Device revocation closes streams, rejects old approvals and requests cancellation of that device's owned activity. Normal disconnection does not cancel a turn. Approval replies must match the live device generation and lease, and authorization is checked again after asynchronous preparation/approval.

Mutations persist a recognized 24-hour epoch and original operation ID before dispatch. Receipts remain at least seven days beyond expiry. Unknown results require history reconciliation; they are never automatically repeated. A crash retains uncertain native activity and project locks. Local recovery refuses a live owner process and requires explicit confirmation of the exact uncertain-activity digest after the operator stops that work on the host. It never discovers or kills unrelated host processes. Legacy recorded container activity must be resolved with the previous release before upgrading.
